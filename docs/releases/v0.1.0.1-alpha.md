# QControl 0.1.0.1 alpha

This alpha adds an explicit unauthenticated qBittorrent connection mode for
installations that already bypass Web UI authentication for Jellyfin's source
address.

## Changes from 0.1.0.0

- Adds **No authentication (qBittorrent bypass)** to the administrator page.
- Sends no `Authorization` header when that mode is selected.
- Requires a successful read-only connection test before enabled actions run.
- Keeps stored credentials until the administrator explicitly clears them.
- Allows accepted queued starts up to five seconds to become observable during
  manual marked-torrent recovery.
- Preserves the qBittorrent 5.2 minimum, API allowlist, version checks, bounded
  timeouts, and all protection/recovery behavior.

## Operator note

QControl does not configure qBittorrent's bypass. Limit bypass to Jellyfin's
source address or the narrowest trusted subnet. The qBittorrent localhost
setting usually does not cover Jellyfin in a separate container.

## Compatibility

- Jellyfin Server `10.11.11` / plugin ABI `10.11.11.0`
- qBittorrent `5.2.3` / Web API `2.15.1`
- .NET `9.0`

The container contract enables qBittorrent's subnet bypass only for the exact
Jellyfin container address, proves the no-header connection through the
packaged plugin, then disables bypass before running the established
authenticated protection and recovery checks.
